# Electron Agent Debug

Electron 应用运行时诊断工具，连接本地已运行的应用，读取主进程与渲染进程日志，并支持代码执行、条件等待、截图和无障碍树快照。

## 功能简介
本技能解决 Agent 修改 Electron 代码后无法确认应用实际运行结果的问题。随包运行时以只连接（attach-only）方式接入已运行的应用，通过主进程 Inspector、渲染进程 CDP 和 utility process 三个通道（可只连其中一部分），提供 8 个工具：连接、状态、target 选择、统一日志时间线（带 seq 游标）、代码执行、条件等待、截图（保存为文件）和无障碍树文本快照。可注册为本地 stdio MCP Server，也可用批处理模式 `launch.cjs --run` 不注册直接调用，`launch.cjs --tools` 列出每个工具的参数。运行时不启动、停止或重启应用，应用由 Agent 用项目已有命令启动；业务回归和最终结论由 Agent 完成。读取日志时可用 sinceAttach 只看本次连接之后的事件，不含 attach 时重放的应用历史输出；日志缓冲区写满后会丢弃最旧的事件，读取日志时返回 droppedThroughSeq 和 gap，提示所请求的范围内是否可能缺失事件。日志、代码执行结果和异常中的常见密钥（含 JWT、常见厂商令牌、私钥块和 URL 中的密码）会被脱敏。渲染进程页面崩溃时，状态会标为离线并返回 TARGET_CRASHED，页面重新加载后自动恢复；应用已打开 DevTools 窗口或 webview 时不影响窗口的自动选择，webview 可显式选择后检查；原来检查的窗口被重建、自动改选了另一个页面时返回 TARGET_CHANGED 警告，避免把别的页面的证据当成目标窗口的。连接失败时保留底层报错并给出定位建议，区分端口没人监听、端口不是调试端口、主进程和渲染进程端口传反，以及端口上是浏览器而不是 Electron。截图默认按页面的 CSS 尺寸保存，高分屏不成倍放大，可用 maxWidth 再缩小。页面的 alert/confirm 和主进程的原生对话框打开时，状态里会列出并标明是否阻塞进程，期间的请求超时会说明原因。

## 适用场景
- **主进程或窗口修改后的运行时验证**：修改主进程启动逻辑、BrowserWindow 创建后，确认窗口真实状态
  - 示例：我改了主进程的窗口创建逻辑，帮我启动应用并验证窗口是否正常显示

- **渲染进程白屏或前端异常排查**：页面白屏、加载失败或出现运行时错误时，查看日志、截图和无障碍树
  - 示例：应用启动后窗口是白屏，帮我看看渲染进程日志和页面实际内容

- **preload、contextBridge 与 IPC 链路验证**：同时取得主进程与渲染进程两侧的证据，并验证完整调用链
  - 示例：我改了 preload 暴露的接口，帮我验证渲染进程调用后主进程是否收到并返回正确结果

- **崩溃或意外退出分析**：结合应用进程退出码与退出前的日志定位问题
  - 示例：应用启动几秒后自己退出了，帮我找原因

- **utility process 内代码的检查**：`electron_attach` 传入 utility 的名字或 pid，工具通过主进程找到进程并打开调试口，作为独立通道与主进程、渲染进程同时在线，可像主进程一样求值和读日志
  - 示例：我的 utilityProcess 里的任务没有执行，帮我连上它看日志和状态

## 不适用场景
- **打包后的应用**：仅支持本地开发环境中由开发命令启动的应用，安装包或已关闭调试开关、fuse 的构建不在支持范围内
- **纯类型检查或构建问题**：没有运行时观察需求，直接使用项目已有的检查即可
- **原生对话框、系统菜单的自动化操作**：此类步骤会提示用户人工操作并确认，再用日志或代码执行核对结果
- **断点、真实输入、网络抓包与性能分析**：不提供，SKILL.md 给出了用日志、求值等替代做法及限制
- **启动或管理应用进程**：只连接已运行的应用，不负责启动、停止或重启
- **远程或非回环地址的应用**：只允许连接本机回环地址

## 依赖要求
| 类别 | 说明 |
|------|------|
| 系统依赖 | Node.js 20 或更高版本；运行文件已随包提供，无需额外下载、安装依赖或构建 |
| 外部服务 | 无 |
| 权限要求 | 待诊断的应用需以 --inspect（主进程）和/或 --remote-debugging-port（渲染进程）参数运行；连接 utility process 需要主进程通道在线且未禁用代码执行，默认调试口 9229 被占用时需给 fork 加 --inspect-port（已在 Windows、macOS、Linux 上实测）；MCP 注册可选，批处理模式无需注册；宿主可通过环境变量 ELECTRON_DEBUG_ALLOW_EVAL=0 禁用代码执行 |

## 使用方式
### 输入格式
描述要验证的 Electron 修改或要排查的现象，并提供项目目录和启动方式，例如：我修改了 preload 的 IPC 接口，项目用 npm run dev 启动，请验证渲染进程到主进程的调用链是否正常。

### 输出示例
验证报告，包含结论（PASS、FAIL 或 BLOCKED）、预期行为、使用的工具与关键证据（日志、截图路径、无障碍树、代码执行结果）、所选 target 以及剩余限制。

## 故障排除
### 渲染进程通道不可用
**出现原因**：环境中设置了 ELECTRON_RUN_AS_NODE=1，Electron 按 Node 运行，不会创建窗口。
**解决方案**：启动应用前取消该环境变量后重试。

### 主进程通道连接失败而渲染进程正常
**出现原因**：应用关闭了 EnableNodeCliInspectArguments fuse，--inspect 参数被忽略。
**解决方案**：改用未关闭该 fuse 的开发构建。

### 截图超时
**出现原因**：窗口被隐藏或最小化时，Chromium 不会响应截图。
**解决方案**：先显示窗口再截图。

### 请求一直超时
**出现原因**：页面的 alert/confirm 或同步的原生对话框正在等用户操作，对应进程在关闭前不响应。
**解决方案**：查看状态里的 dialogs，请用户关闭对话框后重试。

### 应用该退出了但进程还在
**出现原因**：Node 会等已连接的检查器断开才让进程退出，输出里会有 Waiting for the debugger to disconnect…。
**解决方案**：需要退出码或要重启时，直接终止进程，或先结束 MCP 会话。

### 主进程代码执行提示 require 未定义
**出现原因**：主进程全局作用域可能没有 require（例如 ESM 主进程）。
**解决方案**：使用 process.mainModule.require('electron') 获取模块。

## 经典案例
### 案例一：验证 IPC 修改
**背景**：修改了 preload 暴露的接口和主进程的 IPC handler，需要确认调用链真实可用。

**使用流程**：
1. Agent 用项目已有命令启动应用，并加上 --inspect 与 --remote-debugging-port 参数
2. 连接应用，等待明确的就绪日志
3. 在渲染进程执行调用，在主进程读取处理结果
4. 对照日志与截图，给出 PASS、FAIL 或 BLOCKED 结论

**效果收益**：主进程与渲染进程两侧都有运行时证据，避免只凭"没有报错"判断通过。
